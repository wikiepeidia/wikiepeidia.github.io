# Stack Research

## Hugo Version

- **Recommended**: Hugo Extended v0.128+ (latest stable as of early 2026 is ~0.143.x)
- Use **Extended** edition — required by hugo-theme-terminal for SCSS processing
- Install via: `winget install Hugo.Hugo.Extended` on Windows, or download from GitHub releases
- **Key change to watch**: Hugo v0.123+ uses `hugo.toml` as default config filename (was `config.toml`); both still work
- **Modules system**: Hugo v0.56+ has native Hugo Modules (Go modules); older approach uses git submodules. Both work for theme installation

## hugo-theme-terminal Setup

- **Repo**: https://github.com/panr/hugo-theme-terminal
- **Version**: v3.x (actively maintained, ~5k stars)
- **Installation method**: Git submodule (most stable, no Go toolchain required)
  ```bash
  git submodule add https://github.com/panr/hugo-theme-terminal themes/terminal
  ```
- **Config format**: TOML (`hugo.toml`) — theme examples use TOML
- **Light mode**: Theme supports `colorTheme` param — set to `"pink"` or `"orange"` or `"green"` for light-friendly palettes; default is dark. Set `defaultTheme = "light"` in params.
- **Known issues**: 
  - Theme doesn't support Hugo Modules natively (use submodule)
  - Requires post archetype — use `hugo new posts/my-post.md`
  - Cover images in posts use `cover` frontmatter param

## GitHub Actions / Deployment

**Official approach (2026)**: Use GitHub's official Hugo deploy action

```yaml
# .github/workflows/hugo.yml
name: Deploy Hugo site to Pages
on:
  push:
    branches: ["main"]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: "pages"
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          submodules: recursive  # REQUIRED for theme submodule
          fetch-depth: 0
      - name: Setup Hugo
        uses: peaceiris/actions-hugo@v3
        with:
          hugo-version: 'latest'
          extended: true  # REQUIRED for hugo-theme-terminal
      - name: Build
        run: hugo --minify
      - name: Upload artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: ./public
  deploy:
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    needs: build
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
```

- **Repo Settings**: Go to Settings → Pages → Source → GitHub Actions
- **baseURL**: Must be set to `https://wikiepeidia.github.io/` in hugo.toml

## Useful Extras

- **Syntax highlighting**: Built into Hugo (Chroma) — zero config needed, 250+ languages
- **RSS feed**: Auto-generated by Hugo at `/index.xml` — add `[outputs]` section to hugo.toml to also generate section feeds
- **Sitemap**: Auto-generated at `/sitemap.xml`
- **Reading time**: hugo-theme-terminal shows this by default in post metadata

## What NOT to Use (and why)

| Skip | Why |
|------|-----|
| Hugo Modules for theme | Requires Go toolchain; git submodule is simpler for this setup |
| Disqus/comments | Adds third-party tracking, maintenance overhead — out of scope |
| Algolia search | Overkill for a small personal blog |
| PaperMod | Cleaner but lacks the terminal aesthetic the owner wants |
| CDN (Cloudflare Pages) | GitHub Pages is free and sufficient; no need for extra infra |
| Custom SCSS overrides | hugo-theme-terminal is pre-styled; avoid heavy customization for low-maintenance |
